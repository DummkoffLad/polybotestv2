<feature>
  <name>StrategyComparator</name>
  <files>src/statistics/hypothesis.py, tests/unit/test_statistics_hypothesis.py</files>
  <behavior>
    Statistical comparison using scipy.stats.ttest_rel (paired t-test):

    @dataclass ComparisonResult:
      - strategy_a_mean: float
      - strategy_b_mean: float
      - mean_difference: float (b - a)
      - t_statistic: float
      - p_value: float
      - is_significant: bool (p < significance_level)
      - interpretation: str

    StrategyComparator.compare_strategies(
        strategy_a_pnls: List[Decimal],
        strategy_b_pnls: List[Decimal],
        strategy_a_name: str = "Strategy A",
        strategy_b_name: str = "Strategy B"
    ) -> ComparisonResult

    Behavior:
    - Lists must have same length (paired data) -> ValueError if not
    - Uses two-sided t-test (detects difference in either direction)
    - Default significance_level = 0.05
    - Interpretation examples:
      - Significant: "{winner} significantly outperforms (p = 0.0234 < 0.05)"
      - Not significant: "No significant difference between strategies (p = 0.1523 >= 0.05)"

    Test cases:
    - Mismatched lengths -> ValueError
    - Identical lists -> p-value = 1.0, not significant
    - Clearly different (e.g., [1,2,3] vs [10,20,30]) -> p < 0.05, significant
    - Borderline case: verify p-value computed correctly vs scipy reference
    - Empty lists -> handle gracefully (or raise ValueError)
    - Single element lists -> cannot compute t-test, handle appropriately
  </behavior>
  <implementation>
    Use scipy.stats.ttest_rel directly (do NOT reimplement like KellyValidator does).

    Key difference from KellyValidator:
    - KellyValidator hand-rolls t-distribution CDF approximation
    - StrategyComparator uses scipy.stats.ttest_rel for battle-tested accuracy

    Handle edge cases:
    - len(pnls) == 0: raise ValueError("Cannot compare empty lists")
    - len(pnls) == 1: raise ValueError("Cannot compute t-test with single observation")
    - Constant differences (all same): ttest_rel handles this (returns p=nan or 1.0)
  </implementation>
</feature>
