<objective>
Build the LatencySimulator that models realistic API latency (detection delay + execution delay + jitter) and calculates price degradation from delayed execution. This answers "how much PnL do we lose because we can't execute instantly?"

Purpose: The leader's trades are detected with ~1.5s delay and executed with ~2s delay. Price moves during this window degrade our fill price. The simulator quantifies this impact so the validation report can assess whether latency is acceptable.
Output: Working LatencySimulator with TDD tests proving correct delay sampling and price degradation.
</objective>

<feature>
  <name>LatencySimulator</name>
  <files>src/validation/latency_sim.py, tests/unit/test_latency_sim.py</files>
  <behavior>
    LatencySimulator models the full latency pipeline for copy trading.

    LatencyConfig dataclass:
    - detection_delay_ms: float = 1500 (time to detect blockchain event)
    - execution_delay_ms: float = 2000 (time to execute our order)
    - jitter_pct: float = 0.30 (+-30% randomness on each delay)
    - seed: Optional[int] = None (for reproducible testing)

    Predefined configs:
    - LatencyConfig.baseline() -> 1500ms detect + 2000ms execute + 30% jitter
    - LatencyConfig.stress_2x() -> 3000ms detect + 4000ms execute + 30% jitter
    - LatencyConfig.stress_3x() -> 4500ms detect + 6000ms execute + 30% jitter
    - LatencyConfig.zero() -> 0ms delays (no latency, for comparison)

    LatencySimulator class:
    - __init__(config: LatencyConfig)
    - sample_detection_delay() -> timedelta
    - sample_execution_delay() -> timedelta
    - sample_total_delay() -> timedelta (detection + execution)
    - apply_price_degradation(price: Decimal, action: str, delay_ms: float) -> Decimal
      For BUY: price moves UP during delay (worse fill). Model as price * (1 + slippage_rate * delay_s)
      For SELL: price moves DOWN during delay (worse fill). Model as price * (1 - slippage_rate * delay_s)
      Default slippage_rate: 0.001 per second (0.1% per second, conservative for Polymarket hourly markets)

    LatencyImpactResult dataclass:
    - baseline_pnl: Decimal (PnL with zero latency)
    - latency_pnl: Decimal (PnL with latency applied)
    - degradation_dollars: Decimal (baseline_pnl - latency_pnl)
    - degradation_pct: float (degradation / |baseline_pnl| * 100)
    - avg_delay_ms: float (average total delay applied)
    - scenario_name: str (e.g., "baseline", "stress_2x")

    Test cases:
    - sample_total_delay() returns timedelta in expected range (with jitter bounds)
    - Fixed seed produces reproducible delays
    - Zero config produces zero delays
    - Stress 2x produces roughly 2x baseline delays (within jitter bounds)
    - apply_price_degradation for BUY increases price (worse fill)
    - apply_price_degradation for SELL decreases price (worse fill)
    - apply_price_degradation with zero delay returns original price
    - Jitter stays within bounds: delay is always between base*(1-jitter) and base*(1+jitter)
    - LatencyImpactResult correctly computes degradation percentage
  </behavior>
  <implementation>
    Create src/validation/latency_sim.py with LatencyConfig, LatencySimulator, LatencyImpactResult.
    Use random.Random(seed) for reproducible jitter (not global random state).
    Detection and execution jitter are sampled independently.
    Price degradation is a simplified model: linear slippage proportional to delay.
    This is conservative -- actual price impact depends on order book depth, which we don't have in replay.
    The simulator produces price adjustments; the pipeline (Plan 05) applies them during replay.
  </implementation>
</feature>
