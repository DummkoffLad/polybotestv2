  <name>Task 2: Implement latency analysis with post-process ExecutedTrade wiring</name>
  <files>src/validation/pipeline.py</files>
  <action>
    Add the run_latency_analysis() method to ValidationPipeline with concrete latency wiring.

    Approach: Post-process ExecutedTrade records (approach b from checker feedback).
    The SessionReplayer has no hook for price modification, so we do NOT modify the replayer.
    Instead:
      1. Run replay normally (zero latency) via SimpleOptimizer to get a list of ExecutedTrade records and baseline PnL.
      2. For each latency scenario (baseline, stress_2x, stress_3x):
         a. Create LatencySimulator with that scenario's LatencyConfig
         b. Iterate over the ExecutedTrade records from step 1
         c. For each trade:
            - Sample a total delay via latency_sim.sample_total_delay()
            - Compute degraded price = latency_sim.apply_price_degradation(
                trade.our_price, trade.action, delay.total_seconds() * 1000)
            - Compute per-trade PnL delta = (degraded_price - trade.our_price) * trade.shares
              (sign depends on action: for BUY, worse fill = higher price = negative delta;
               for SELL, worse fill = lower price = negative delta)
         d. Sum all per-trade PnL deltas to get total latency cost
         e. latency_pnl = baseline_pnl + total_latency_cost (cost is negative)
         f. Build LatencyImpactResult with baseline_pnl, latency_pnl, degradation amounts

    This approach is accurate enough for validation because:
    - Small price deltas (0.1%/s * 3.5s = 0.35%) don't meaningfully change position sizing decisions
    - We care about aggregate PnL impact, not individual trade re-simulation
    - It avoids modifying SessionReplayer internals

    Complete the run_full_validation() method:
      1. run_out_of_sample() -> get session PnLs
      2. Use KellyValidator.bootstrap_confidence_interval() for CI
      3. run_sensitivity() on first out-of-sample session (representative)
      4. run_latency_analysis() on first out-of-sample session
      5. Aggregate into ValidationSummary
      6. Generate and save report via report_gen
      7. Print console summary
      Returns the full ValidationSummary.

    Note: The ExecutedTrade records need to be obtained from the replay. Check SimpleOptimizer
    return value -- if it doesn't return individual trades, access them via the strategy's
    executed_trades attribute or the session recorder. If no per-trade records are available,
    fall back to estimating latency cost as: baseline_pnl * (slippage_rate * avg_delay_s * num_trades).
    Document whichever approach is used.
