  <name>Task 1: Create src/core/trade_logic.py with shared liquidation logic</name>
  <files>src/core/trade_logic.py (new), src/core/__init__.py</files>
  <action>
    Create `src/core/trade_logic.py` containing the shared hour boundary liquidation function.

    The function `liquidate_positions_at_hour_boundary()` should:
    1. Accept a Portfolio instance, a dict of current prices (Dict[str, PriceSnapshot]), and optional entry_prices dict and tracking dicts (our_entries, high_water_marks)
    2. Iterate all open positions from portfolio.get_positions()
    3. For each position with shares > 0:
       - Get the price snapshot for that token
       - If bid is available and not None, use it as last_bid
       - If no price data, fall back to entry_prices if provided, else default to 0.50
       - Determine resolution price: if last_bid >= 0.50 then $0.99 (win), else $0.01 (loss)
       - Call portfolio.apply_sell() with full shares at resolution price
       - Calculate dollars = shares * resolution_price
       - Remove token from our_entries and high_water_marks if provided
       - Log the resolution
    4. Return a LiquidationResult dataclass with: total_dollars, num_sells, and per-position details

    This logic is currently duplicated in:
    - `src/strategies/profit_taker/strategy.py` lines 218-252 (`_liquidate_hour_boundary`)
    - `src/framework/replay/replayer.py` lines 132-167 (`_liquidate_all_positions`)

    Key differences to reconcile:
    - profit_taker uses resolution prices ($0.99/$0.01 based on bid >= 0.50)
    - replayer uses actual bid prices for liquidation (not resolution prices)
    - The shared function should support BOTH modes via a `use_resolution_prices: bool` parameter
      - True (default): Use $0.99/$0.01 resolution logic (for hour boundary in strategies and runner)
      - False: Use actual bid prices (for replayer mid-session liquidation)

    Also update `src/core/__init__.py` to export the new function.

    IMPORTANT: The function must work with the composite-keyed Portfolio from Plan 08-01. The get_positions() return uses composite keys, so the function iterates those.
  </action>

