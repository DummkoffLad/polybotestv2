<feature>
  <name>Portfolio composite position keying</name>
  <files>src/core/portfolio.py, tests/unit/test_portfolio.py</files>
  <behavior>
    The Portfolio class must key positions by a composite of (token_id, market_id, side) instead of bare token_id.

    Test cases (input -> expected):
    1. Buy "tok_A" in "market_1" UP, then buy "tok_A" in "market_2" UP:
       -> Two separate positions, each with independent shares/cost_basis
    2. Buy "tok_A" in "market_1" UP, then buy "tok_A" in "market_1" DOWN:
       -> Two separate positions (different sides)
    3. Buy "tok_A" in "market_1" UP twice:
       -> Single position with accumulated shares (same as before)
    4. get_positions() returns dict keyed by composite key string (e.g., "tok_A|market_1|UP")
    5. has_position("tok_A", "market_1", Side.UP) returns True only for that exact combo
    6. get_market_exposure("market_1") sums all positions in that market
    7. get_side_exposure("market_1", Side.UP) sums all positions for that market+side
    8. calculate_pnl works with composite keys
    9. to_dict() serializes properly with composite keys
    10. clear() resets everything

    Backward compatibility:
    - All callers already pass (token_id, market_id, side) to portfolio.get(), apply_buy(), apply_sell()
    - The change is internal: _positions dict key changes from token_id to composite key
    - get_positions() return type changes: keys become composite key strings
    - has_position() signature changes to accept (token_id, market_id, side)

    Implementation approach:
    - Add a `_position_key(token_id, market_id, side)` static method returning a composite key string
    - Change `_positions` dict to use composite keys
    - Update `get()`, `has_position()`, `apply_buy()`, `apply_sell()` to use composite keys
    - Update `get_positions()` to return composite-keyed dict
    - Update `calculate_pnl()` to iterate composite-keyed positions
    - Update `to_dict()` to serialize with composite keys
    - Keep `get_market_exposure()` and `get_side_exposure()` working (they already filter by market_id/side)

    IMPORTANT: The existing test `test_multiple_markets_same_token_id` is currently marked as documenting a known bug. After the fix, this test should PASS cleanly with the correct behavior (two separate positions).

    IMPORTANT: `has_position()` currently only takes `token_id`. It must be updated to accept `(token_id, market_id, side)` for composite keying. Check ALL callers of `has_position()` in the codebase and update them.
  </behavior>
