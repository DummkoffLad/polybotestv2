# Phase 07.1 Plan 02: Consolidate OrderType Enum

**One-liner:** Remove duplicate OrderType enum from strategies/base.py, import from core/types.py for single source of truth

## What Was Built

Eliminated the duplicate `OrderType` enum definition that existed in both `src/core/types.py` and `src/strategies/base.py`. Now there is a single definition in `core/types.py`, and `base.py` imports it.

**Before:**
```python
# src/strategies/base.py

    MARKET = "MARKET"
    LIMIT = "LIMIT"
```

**After:**

## Technical Notes

### Enum Consolidation Pattern

This establishes the pattern for Phase 07.1:
1. **Central definition:** All shared enums live in `src/core/types.py`
2. **Import, don't duplicate:** Other modules import from core.types
3. **Module re-export:** Intermediate modules (like base.py) can re-export for convenience
4. **Type identity:** Same enum object everywhere prevents comparison bugs

### Why This Matters

Duplicate enum definitions create subtle bugs:
```python
# Before: Two separate OrderType enums
base_order = base.OrderType.MARKET
core_order = types.OrderType.MARKET

# This would fail!
assert base_order == core_order  # False! Different enum objects

# After: Single enum definition
assert base_order is core_order  # True! Same object
```
